# Отчёт о тестировании User Profile API

## 1. Цель тестирования
Проверить основные пользовательские сценарии API: регистрацию, авторизацию, просмотр профиля и изменение данных профиля. Запросы выполняются асинхронно с помощью `httpx.AsyncClient`.

## 2. Объект тестирования
Разработано тестовое API на FastAPI со следующими методами:

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/api/register` | Регистрация пользователя |
| POST | `/api/login` | Вход в систему |
| GET | `/api/profile` | Получение профиля по Bearer-токену |
| PUT | `/api/profile` | Изменение email и имени |
| POST | `/api/logout` | Выход из системы |

## 4. Использованные инструменты
- Python — язык реализации.
- FastAPI — асинхронное веб-приложение и API.
- pytest — запуск и организация тестов.
- pytest-asyncio — поддержка асинхронных тестовых функций.
- `pytest.mark.asyncio` — маркировка асинхронных тестов.
- `event_loop` — фикстура создания цикла событий.
- httpx — отправка асинхронных HTTP-запросов.
- Allure — формирование расширенного тестового отчёта.

## 5. Результаты запуска
В проекте подготовлено 13 автоматизированных тестов: 1 успешная регистрация, 3 негативных сценария регистрации, 3 сценария авторизации, 3 сценария просмотра профиля и 3 сценария редактирования профиля.

Команда запуска:

```bash
pytest
```

Ожидаемый результат при корректной установке зависимостей:

```text
collected 13 items
13 passed
```

**Важно:** это ожидаемый результат тестового набора, а не заявление о фактически выполненном запуске на компьютере заказчика. Фактические цифры и предупреждения необходимо внести после запуска `pytest` в целевом окружении.

## 6. Ошибки и предупреждения
В тестовом проекте предусмотрены проверки ожидаемых ошибок API:
- 401 Unauthorized — отсутствующий, неверный токен или неверные данные входа;
- 409 Conflict — повторная регистрация занятого имени пользователя;
- 422 Unprocessable Entity — некорректный email или пароль, не соответствующий ограничениям.

При использовании разных версий `pytest-asyncio` поведение фикстуры `event_loop` может отличаться. В проекте используется собственная фикстура `event_loop` для демонстрации требования задания. Если установленная версия плагина выдаёт предупреждение о переопределении цикла событий, следует согласовать область цикла с версией `pytest-asyncio` и использовать рекомендуемый для неё способ управления loop scope.

## 7. Рекомендации по улучшению приложения
1. Хранить пользователей и сессии в базе данных, а не в оперативной памяти.
2. Использовать проверенную схему хеширования паролей (например, Argon2id или bcrypt) и никогда не хранить пароль в открытом виде.
3. Реализовать срок действия, отзыв и безопасное обновление токенов.
4. Добавить тесты выхода из системы, истечения токена, повторного email, слишком длинных значений и граничных случаев.
5. Проверить разграничение доступа: пользователь должен иметь доступ только к собственному профилю.
6. Добавить rate limiting для входа и регистрации, журналирование и безопасную обработку ошибок.
7. Запускать тесты в CI при каждом изменении кода.

## 8. Вывод
Подготовлен набор асинхронных API-тестов, проверяющий основные положительные и отрицательные сценарии регистрации, входа, просмотра и редактирования профиля. Тесты используют `pytest`, `pytest.mark.asyncio`, фикстуры и `httpx.AsyncClient`. Проект можно расширять новыми сценариями и подключить к CI/CD.
